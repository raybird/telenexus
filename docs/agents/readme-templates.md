# Issue README 範本

> 建立或更新 issue README 時載入。核准形式與來源依 [acceptance.md](acceptance.md)，測試策略依 [verification.md](verification.md)。

建立 issue README 時套用；依規模擇一，Medium / Large 用標準格式，Small 用輕量級格式。

## README.md 範本

### 標準格式（Medium / Large）

建立 README 時，`## 文件清單` **只能套用下列其中一種**，且只能連結該分級實際建立的文件：

**Medium：**

```markdown
## 文件清單
- [implementation-plan.md](./implementation-plan.md)
```

**Large：**

```markdown
## 文件清單
<!-- 下列兩行只在該文件實際建立時保留，建立條件見 docs/AGENTS.md「規模分級」。最終輸出移除本註解。 -->
- [requirement-analysis.md](./requirement-analysis.md)
- [technical-analysis.md](./technical-analysis.md)
- [implementation-plan.md](./implementation-plan.md)
```

其餘共用內容使用以下格式：

````markdown
# Issue {編號} - {標題}

## 概述
{簡要說明議題目標}

## 快速導覽

<!-- 「快速導覽」與「關鍵差異」只在有新舊行為或流程對照時保留；沒有對照可寫時整節移除。 -->

### 當前流程
{流程說明}

### 重構後流程
{流程說明}

## 關鍵差異
| 項目 | 變更前 | 變更後 |
|------|--------|--------|

## 涉及檔案
### {模組名稱}
- `{檔案路徑}` - {說明}

<!-- 邊界含不可觸及區域時，改用 `docs/agents/document-types.md`「邊界與方案的視覺形式」的淺層檔案樹。最終輸出移除此註解。 -->

```gherkin

  @SCN-001
  Scenario: {具體行為}
    Given {已確認的初始狀態}
    When {使用者或系統執行的動作}
    Then {可觀察且可驗證的結果}
```

- **完成證據**：{可觀察、可重複確認的通過條件}

## 待確認事項
````

### 輕量級格式（Small 級別專用）

若為 **Small** 級別的任務，所有的分析與實作計畫將會合併在單一 `README.md` 中：

````markdown

## 概述
{簡要說明問題點與優化目標}

## 涉及檔案
- `{檔案路徑}` - {修改說明}

<!-- 邊界含不可觸及區域時，改用 `docs/agents/document-types.md`「邊界與方案的視覺形式」的淺層檔案樹。最終輸出移除此註解。 -->

1. **AC-1**：{可觀察結果} — 檢查方式：{可重複執行的命令或步驟}
````

> [!NOTE]
> `**狀態**` 欄位在建立當下應填寫實際狀態（例如「待實作」），**不要預先寫成「已完成」**——`dev-cycle` 依此欄位追蹤進度，依實際結案依據更新；不修復保留原狀態。Timeline 依事件的實際日期記錄，同日發生可同日，不另造完成日期。
