### 標註標準

**相關題**
- 每題對應副本裡一段使用者交代過的決定、規則或研究，問法改寫成之後回頭問的口吻。
- 目標 session 是 summary 含有答案關鍵字句的 session，用 LIKE 樣式解析出來，一題可以有多個目標：
  - 31 題只有 1 個目標，最多一題有 15 個；
  - 50 題都至少有 1 個目標。
- 主題分類：
  - 排程設定：時間、暫停、移除、範圍；
  - 工作規則：git 流程、作者身分、用詞、核心程式碼不能改、暫存路徑、部署檢查；
  - 專案決策：架構目標、是否繼續、參考哪個 repo、版本格式；
  - 外部 repo 與模型的研究結論；
  - 命理排程的內容要求。

**無關題**
- 日常問題 28 題，例如料理、健康、寵物、家事、旅遊、職場。
- 含數字的計算與換算 22 題。
- 每題的主要關鍵詞都先在副本的 `user:` 分區用 LIKE 確認過：
  - 有 2 題在副本裡找得到相關主題，凍結前換掉了。一題是颱風（副本有查颱風動態的對話），一題是小孩作息（副本有談到子女的占卜）。
  - 另外 3 題的關鍵詞只是剛好出現在別的主題裡（咖啡豆的商品新聞、視覺小說、二次方成長），沒有換。

## 指標

腳本：[scripts/collect-recall.mjs](scripts/collect-recall.mjs) 收集原始回應，[scripts/evaluate.mjs](scripts/evaluate.mjs) 計算指標。

- payload 和 `MemoriaRecallClient.recallWithMeta` 相同：`project=TeleNexus`、`scope=user:<id>`、`top_k=5`、`mode=hybrid`。
- 相關命中：判準決定注入，而且注入的結果（snippet 不是空白的 hit）裡有目標 session。
- 無關注入：判準決定注入，而且至少有一筆 snippet 不是空白。

### 無關題命中的是哪些 token

- 依 Memoria 1.28.1 的 `tokenizeQuery` 算出問句的 token，再對第一筆結果的 summary 比對。
- 被注入的無關題，命中的 token 幾乎都是疑問詞與虛詞組成的 2 字窗格，例如「什麼」「怎麼」「為什」「多少」「有沒」「要怎」「麼好」「有幾」「幾個」。
- 只有數字命中的很少。調整集只有 1 題是數字 `24` 加上「小時」。
- 相關題排名正確時，命中的大多是內容詞：專案名、英文名稱、主題詞。

因此 #15「數字 token 撞上數字」的推測在調整集上只是次要因素。主要是 Memoria 的覆蓋率把疑問詞也算成命中，而短問句的 token 少，碰巧命中兩三個就超過 0.2。
