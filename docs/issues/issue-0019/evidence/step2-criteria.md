# 步驟 2：候選判準與驗收集結果

- **日期**：2026-10-21
- **對應**：AC-2
- **資料、Memoria 與指標**：同 [step1-evaluation-set.md](step1-evaluation-set.md)

## 候選判準（只用調整集）

判準由兩部分組成：

1. **送出前的問句改寫**
   - `none`：原句。
   - `strip-digits`：拿掉數字。
   - `strip-function-words`：拿掉疑問詞與虛詞，清單見 [scripts/function-words.mjs](scripts/function-words.mjs)，換成空白，前後的字不會組成新的窗格。
2. **注入條件**
   - `confidence ≥ threshold`；
   - 而且命中的 token 數 ≥ `minMatched`。命中數是 `round(confidence × token 數)`，token 數依 Memoria 1.28.1 的 `tokenizeQuery` 對送出的問句計算，所以不需要 snippet 原文。

調整集上的部分結果。完整網格是 3 種改寫 × 8 個門檻 × 3 個 minMatched，以 `evaluate.mjs --grid` 重現：

| 改寫 | 門檻 | minMatched | 相關命中 | 無關注入 |
|---|---|---|---|---|
| none（現行） | 0.2 | 1 | 24/33 | 14/33 |
| none | 0.2 | 3 | 24/33 | 5/33 |
| strip-digits | 0.2 | 1 | 23/33 | 15/33 |
| strip-function-words（第一版清單） | 0.2 | 1 | 24/33 | 10/33 |
| strip-function-words（第一版清單） | 0.2 | 2 | 24/33 | 2/33 |
| strip-function-words（第二版清單） | 0.2 | 2 | **24/33** | **1/33** |
| strip-function-words（第二版清單） | 0.3 | 2 | 23/33 | 0/33 |
| strip-function-words（第二版清單） | 0.2 | 3 | 21/33 | 0/33 |

- 只拿掉數字沒有幫助，與 step 1 的 token 分析一致。
- **清單修訂一次**：第一版收了「多少」卻漏了「幾」，調整集的一題以「有幾」「幾個」被注入。第二版依「疑問詞全收」的原則補了「幾」「誰」「何時」，並把「哪些」「哪個」「哪裡」「哪一」併成「哪」。沒有加入任何主題詞。
- **選定**：`strip-function-words`（第二版清單）、門檻 0.2（現行預設不變）、`minMatched=2`。
  - 調整集上：相關命中和現行判準同樣是 24/33，無關注入 1/33（3.0%）。
  - 個別題目有一進一出：選定判準多命中 2 題，少命中另外 2 題，因為改寫後的問句讓 Memoria 的排序也跟著改變。

## 驗收集（判準定案後只跑一次）

定案時腳本的 sha256 前 16 碼：
- `function-words.mjs` `5a9dd9b4545b084d`
- `evaluate.mjs` `94d4af9c41852b30`
- `collect-recall.mjs` `0bf72be038774f17`

| 判準 | 相關命中 | 無關注入 |
|---|---|---|
| 現行（none、0.2、1） | 14/17（82.4%） | 8/17（47.1%） |
| 選定（strip-function-words、0.2、2） | **15/17（88.2%）** | **4/17（23.5%）** |

- 相關命中不低於現行判準：**成立**。
- 無關注入率 ≤ 10%：**不成立**。17 題最多只能有 1 題被注入，實際有 4 題。

### 驗收集上仍被注入的 4 題（只做診斷，判準沒有依此修改）

| 題號 | 類型 | 命中的 token |
|---|---|---|
| C02 | 含數字的計算 | 兩個數字（就是 #15 的「17 乘以 23」） |
| C36 | 含數字的換算 | 一個數字加上「小時」 |
| C17 | 日常 | 「要注」「注意」：「要」不在清單裡，和下一個字組成窗格 |
| C48 | 日常 | 「設定」「定在」：一般動詞 |

- 驗收集有 2 題是數字造成的。調整集只有 1 題，而且只拿掉數字的改寫在調整集上沒有效果，所以這個方向不是從調整集推得出來的。
- 驗收集的含數字無關題是 7/17，比調整集的 15/33 稍多。
- 另外 2 題是一般詞彙碰巧命中。這是字面覆蓋率本身的限制：只要問句與某段對話共用兩個一般詞，覆蓋率就無法分辨相關與否。

依 AC-2，達不到門檻時回報最佳取捨，由使用者決定。決定記錄在 README。

## 第二版：全新驗收集（使用者 2026-10-21 選「做第二版＋全新驗收集」）

### 新驗收集（先凍結，再設計第二版）

- 在設計第二版之前就寫好並凍結，sha256 `3f048252f9e9d718832ca55b48ed222380d6c9a5320698fcd3778099bf6e3e40`。
- 組成：相關題 17（含數字 2）、無關題 17（含數字 7）。主題與舊的 100 題都不重複，標註標準同 step 1。
- 無關題的關鍵詞檢查：有 3 個詞只是剛好出現在別的主題裡（比喻用的「噪音」、「閱讀」、腳本裡的 `sleep 3600`），沒有換題。
- 腳本：`freeze-eval-set.mjs --all-acceptance`。

### 調整：舊的 100 題全部當調整集

舊驗收集的結果已經看過，不能再當驗收用，所以和舊調整集合併成 100 題的調整集，稱為 pool。另外比較兩個方向：

- **單字虛詞**（`strip-function-words-v2`）：再拿掉代名詞、助動詞、介系詞與副詞的單字，清單是 `SINGLE_CHAR_FUNCTION_WORDS`。目的是避免「要注」這類由虛詞和內容字組成的窗格被當成命中。
- **命中數的算法**（`--count`）：
  - `confidence`：第一版的算法，`round(confidence × token 數)`。
  - `snippet-top`：不是純數字的 token 出現在第一筆 snippet 的個數。數字不計入命中，也只算實際會注入的那段文字。
  - `snippet-any`：同上，但算所有注入的 snippet。

pool 上的部分結果（門檻 0.2、minMatched 2）。完整網格以 `evaluate.mjs --grid` 重現：

| 改寫 | 命中數算法 | 相關命中 | 無關注入 |
|---|---|---|---|
| none（現行，minMatched 1） | confidence | 38/50 | 22/50 |
| strip-function-words | confidence（第一版） | 39/50 | 5/50 |
| strip-function-words | snippet-top | 39/50 | 2/50 |
| strip-function-words-v2 | confidence | 39/50 | 3/50 |
| strip-function-words-v2 | **snippet-top** | **39/50** | **0/50** |
| strip-function-words-v2 | snippet-any | 39/50 | 6/50 |

- `snippet-any` 比 `snippet-top` 差：多筆 snippet 加起來，更容易湊到兩個一般詞。
- **選定**：`strip-function-words-v2`、門檻 0.2、`minMatched=2`、`snippet-top`。
- pool 上 0/50 很可能有過度貼合，所以以新驗收集的結果為準。

### 已知限制

- 新驗收集的相關題比舊的容易：每題的 confidence 最低 0.455，舊調整集最低 0.176。所以兩種判準的相關命中都是 17/17，這組題目分不出兩者在相關題上的差異。相關命中的比較主要依 pool 的 39/50 對 38/50。
- 評估集只來自一份部署的資料，而且全部走字面路由。
- `snippet-top` 看的是 Memoria 回傳的前 200 字 snippet（`buildSnippet`）。答案關鍵字在 200 字之後的對話，命中數會偏低。
- token 的切法複製自 Memoria 1.28.1 的 `tokenizeQuery`。Memoria 改了切法時，這裡要跟著改。
